# 00 — Koneksi Database

Aplikasi memakai PostgreSQL melalui SQLx. Saat startup, `main.rs` membaca `DATABASE_URL`, membuat `PgPool` dengan maksimum lima koneksi, lalu menghentikan proses jika koneksi gagal.

## Pool dan koneksi

`PgPool` adalah pengelola koneksi yang dapat dipakai bersama oleh banyak request. Handler menerima pool melalui `State<PgPool>`. Middleware menerima pool melalui `Extension<PgPool>`, kemudian memanggil `pool.acquire()` ketika perlu menjalankan pemeriksaan akun.

Ada dua bentuk parameter database di model:

- `&PgPool`: model barang dan riwayat membiarkan SQLx mengambil koneksi dari pool saat query dijalankan.
- `&mut PgConnection`: model login dan middleware memakai koneksi yang sudah diambil dengan `pool.acquire()`.

Setelah fungsi selesai, koneksi dikembalikan ke pool.

## Tabel yang digunakan kode

Kode menggunakan tabel `users`, `gudang`, `barang`, dan `riwayat_stok`.

| Tabel | Data yang dipakai aplikasi |
|---|---|
| `users` | `id`, `username`, `password`, `aktif`, `role`, `gudang_id` |
| `gudang` | Pemeriksaan apakah gudang dengan ID tertentu ada |
| `barang` | `id`, `nama`, `stok`, `harga`, `gudang_id` |
| `riwayat_stok` | `id`, `barang_id`, `nama_barang`, `gudang_id`, `stok_lama`, `stok_baru`, `waktu_perubahan` |

Model menggunakan `NUMERIC` PostgreSQL untuk `harga` dan memetakannya ke `rust_decimal::Decimal`. Model membaca `waktu_perubahan` sebagai teks melalui cast SQL.

Repository menyediakan lima file migration di `migrations/`. Migration tersebut mendefinisikan struktur tabel, constraint, relasi, serta function dan trigger database. Ringkasan schema yang didefinisikan migration:

| Tabel | Struktur dan aturan penting |
|---|---|
| `gudang` | `id BIGINT GENERATED BY DEFAULT AS IDENTITY` sebagai primary key; `nama_gudang VARCHAR(100)` wajib diisi dan unik. |
| `users` | `id BIGSERIAL` primary key; `username VARCHAR(50)` dan `password VARCHAR(255)` wajib diisi; username unik; `created_at TIMESTAMP WITH TIME ZONE` wajib diisi dengan default `NOW()`; `role VARCHAR(30)` dan `gudang_id BIGINT` boleh `NULL`; `aktif BOOLEAN` wajib diisi dengan default `FALSE`. Role dibatasi ke `admin` atau `petugas_gudang`; constraint role-gudang mengizinkan admin aktif tanpa gudang, petugas aktif dengan gudang, atau akun belum aktif tanpa role dan gudang. |
| `barang` | `id SERIAL` primary key; `nama VARCHAR(100)`, `stok INTEGER`, `harga NUMERIC(12, 2)`, dan `gudang_id BIGINT` wajib diisi; stok default `0`; `created_at` dan `updated_at TIMESTAMP WITHOUT TIME ZONE` wajib diisi dengan default `CURRENT_TIMESTAMP`; stok dan harga tidak boleh negatif. |
| `riwayat_stok` | `id SERIAL` primary key; `barang_id INTEGER` boleh `NULL`; `stok_lama` dan `stok_baru INTEGER`, `nama_barang TEXT`, serta `gudang_id BIGINT` wajib diisi; stok lama dan baru tidak boleh negatif; `waktu_perubahan TIMESTAMP WITHOUT TIME ZONE` boleh `NULL` dan memiliki default `CURRENT_TIMESTAMP`. |

`users.gudang_id` dan `barang.gudang_id` merujuk ke `gudang.id`; penghapusan gudang yang masih dirujuk dibatasi (`ON DELETE RESTRICT`). `riwayat_stok.gudang_id` juga merujuk ke `gudang.id` dengan aturan yang sama. `riwayat_stok.barang_id` merujuk ke `barang.id`; jika barang dihapus, nilai relasi itu menjadi `NULL` (`ON DELETE SET NULL`). Snapshot `nama_barang` dan `gudang_id` di riwayat membuat identitas barang dan gudang pada catatan perubahan tetap tersedia setelah barang dihapus.

Migration juga membuat index pada `users.gudang_id` dan `barang.gudang_id`.

Trigger memperbarui `barang.updated_at` pada setiap UPDATE barang. Trigger pencatatan stok berjalan pada UPDATE kolom `stok` dan membuat riwayat hanya jika nilai stok benar-benar berubah. Catatan menyimpan stok lama, stok baru, serta snapshot nama barang dan gudang dari data barang setelah perubahan.

File migration tersedia di repository, tetapi backend tidak menjalankannya secara otomatis saat startup. Keberadaan file tersebut menjelaskan struktur yang didefinisikan; hal itu tidak membuktikan migration sudah diterapkan pada database yang digunakan. Startup aplikasi hanya membuka koneksi dan tidak memeriksa atau mengubah status penerapan migration.

## Alur

```text
DATABASE_URL → PgPoolOptions → PgPool
                         ├→ State<PgPool> → controller → model → PostgreSQL
                         └→ Extension<PgPool> → middleware → PostgreSQL
```

Secret dan URL database harus disimpan sebagai environment variable. Jangan menaruh kredensial nyata di dokumentasi atau source code.
